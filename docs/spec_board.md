# 案件掲示板（企業間の案件掲載・案件チャット・人材提案）仕様

既存の「募集・応募」（個人スタッフ向けの公開募集ページ）とは別の、**利用企業どうしが案件と人材をやり取りする場**。
システム外での取引は制限しない。その代わり「スキルシートの作り直し不要・提案状況の一覧管理・成約後のスタッフ登録/シフト割当まで一気通貫」で、
システム上で進めた方が手間がない状態を目指す。

## 0. 決定事項（2026-10 ユーザー確認済み）
| 項目 | 決定 |
|---|---|
| 掲載企業名 | 公開する |
| 公開範囲 | 全利用企業（相手先指定は将来対応） |
| 提案時の公開範囲 | 2段階（提案時は匿名プロフィール、採用で氏名を開示） |
| 取引先所属スタッフの提案 | 可。「取引先所属」と明示 |
| 他社連携・統合済みスタッフの提案 | 可。提案時に注意文を表示 |
| 頭超え防止 | 取り込んだ企業からは**直前の提案企業名のみ**見える。2次・3次受けでも案件元からは一つ前の企業しか分からない。経路データは保持するが画面・APIには出さない |
| 単価 | 掲載時に**必須**。備考（「スキルにより交渉可能」「応相談」等）を付けられる |
| 利用権限 | 管理系ユーザー全員（company_admin / sales_manager / field_manager / office_staff）。権限の細分化は他機能完成後に再設計 |
| プラン制限 | 当面なし |

## 1. 画面
サイドメニューに「案件掲示板」を追加（未読バッジ付き）。
- **一覧**: タブ「常勤」「スポット」×「掲載中 / 自社の掲載 / やり取り中」。エリア・期間・スキル・キーワードで絞り込み
- **掲載の作成/編集**: 自社案件からのコピー作成可。状態は 下書き → 掲載中 → 締切 / 充足
- **詳細**: 掲載内容 + 「問い合わせる（チャットを開く）」。掲載企業側は問い合わせ企業ごとのスレッド一覧
- **案件チャット**: 掲載1件 × 問い合わせ企業1社の1対1スレッド。メッセージと人材提案カードが時系列に並ぶ
- **人材提案**: チャット内「人材を提案」→ 自社スタッフマスタから選択 → 送る内容のプレビュー → 送信

## 2. 掲載（board_posts）
| 項目 | 備考 |
|---|---|
| engagement_type | regular（常勤）/ spot（スポット） |
| title, description | 必須 / 任意 |
| prefecture, area, nearest_station | エリア検索用 |
| date_from, date_to, time_from, time_to, schedule_note | 常勤は期間＋「週5・土日含む」等、スポットは日付・時間帯 |
| headcount, required_skills | 人数・求めるスキル（カンマ区切り） |
| **price_amount, price_unit, price_note** | 単価は必須（price_unit = hourly / daily / monthly）。price_note は自由記述＋定型候補 |
| deadline | 締切日。過ぎた掲載は閲覧時に自動で「締切」扱い（cron を使わない遅延処理） |
| status | draft / open / closed / filled |
| source_project_id | コピー元の自社案件（自社内でのみ参照。他社には出さない） |

他社に見せるのは掲載内容と掲載企業名のみ。クライアント名・自社案件の詳細は出さない（掲載文に書くかは掲載企業の判断）。

## 3. 案件チャット（board_threads / board_messages / board_thread_reads）
- スレッド = (post_id, inquirer_company_id) で一意。参加できるのは掲載企業と問い合わせ企業の管理系ユーザーのみ
- 既読は企業単位（既存の企業間チャットと同じ方式）。未読バッジは 1 分ごとに更新
- スタッフ本人向けAPI（/api/staff/*）には一切ルートを持たない
- 履歴は削除しない。システムメッセージ（提案・状態変更）も同じ時系列に記録

## 4. 人材提案（board_proposals）
### 4.1 提案できるスタッフと注意文
| 区分 | 可否 | 表示・注意文 |
|---|---|---|
| 自社雇用・日雇い・個人事業主・スキルシートのみ | 可 | なし |
| 取引先所属 | 可 | 受け手に「取引先所属」バッジ。提案者に「取引先から預かっている人材です。再提案が可能か取引先との契約をご確認ください」 |
| 他社連携 | 可 | 受け手には「取引先所属」と同じ扱いで表示（連携元は出さない）。提案者に「他社から連携されている人材です。所属元との契約上、再提案が可能かご確認ください」 |
| 統合済み | 可 | 提案者に「統合済みのスタッフです。通常は統合先のスタッフで提案してください」 |
| 掲示板経由で取り込んだスタッフ | 可（2次・3次受け） | 受け手には「取引先所属」と表示。提案者に取引先所属と同じ注意文 |

### 4.2 送る内容（スナップショット）
提案時点の内容を JSON で保存し、後でスタッフマスタを編集しても提案内容は変わらない。
- **提案時（匿名）**: イニシャル、年代、性別、最寄駅、通勤可能時間、稼働開始可能日、稼働可能エリア、スキル、経歴テーブル、経験・スキル・人柄・PRポイント等、区分バッジ（自社雇用 / 取引先所属 / 個人事業主 等）、提案コメント、提示単価（任意）
- **採用後に開示**: 氏名・フリガナ
- **送らない**: 所属会社名・所属先担当者名・連絡先・管理者メモ・備考・従業員管理の情報・連携元/取り込み元の企業情報

### 4.3 状態
proposed（提案中）→ interview（面談希望）→ adopted（採用）/ declined（見送り）。提案者は adopted 前なら withdrawn（取り下げ）可。
状態変更はチャットにシステムメッセージとして残る。

## 5. 頭超え防止（経路の秘匿）
- 提案レコードに `proposer_company_id`（直前の企業）と `upstream_chain`（それより上流の企業IDの配列。JSON）を保存
  - upstream_chain = 提案スタッフが「掲示板経由で取り込んだ行」なら、その取り込み元提案の upstream_chain + その提案者
  - 提案スタッフが「他社連携（QR連携）」なら、連携元企業を upstream_chain に入れる
  - 提案スタッフが「取引先所属」なら、取引先名（staff_affiliations）を記録
- **upstream_chain は API レスポンス・画面・CSV に一切出さない**（DB 内のみ。将来のシステム管理者向け監査用）
- 受け手に見える企業名は常に `proposer_company_id` の企業名だけ

## 6. 成約後の取り込み（採用 → 自社スタッフマスタへ）
採用した企業に「スタッフマスタに取り込む」ボタンを表示。
- 取り込んだ行は **affiliation_type = partner_manual（取引先所属）**、所属会社名 = 提案企業名（取引先マスタにも自動登録）
- 基本項目・業務側項目は採用時点の開示内容（氏名＋スナップショット）をコピー。以後は自社で編集可（提案元とは同期しない）
  - 既存の QR 連携（linked_external）は所属元企業名を表示する仕組みのため、頭超え防止の観点から掲示板経由では使わない
- staff_profiles に `board_proposal_id`（取り込み元提案）を記録。画面には「掲示板経由（提案: ○○株式会社）」とだけ表示
- 同じ提案からの二重取り込みは不可
- スポット掲載で自社のシフト枠と紐づけている場合は、取り込み後にシフトボードの割当画面へ遷移（第4段階）
- ログインIDは発行しない（必要なら既存の「本登録」から）

## 7. データモデル（予定）
- `board_posts`（第1段階）
- `board_threads`, `board_messages`, `board_thread_reads`（第2段階）
- `board_proposals`（第3段階）: proposal_id, thread_id, post_id, proposer_company_id, receiver_company_id, staff_id（提案者側の行）, staff_kind, snapshot（匿名 JSON）, disclosed（氏名 JSON）, proposed_price, comment, status, upstream_chain（非公開）, imported_staff_id, 各日時
- `staff_profiles.board_proposal_id`（第4段階）

## 8. 段階リリース
| 段階 | 内容 |
|---|---|
| 1 | 掲載の作成・編集・締切、一覧（常勤/スポット・絞り込み）、詳細、自社案件からのコピー |
| 2 | 案件チャット、既読・未読バッジ |
| 3 | 人材提案（匿名スナップショット・注意文・状態管理・採用で氏名開示）、経路の記録 |
| 4 | 採用後の取り込み（取引先所属として登録・提案企業名のみ表示）、スポットのシフト割当導線 |
| 5（任意） | 新着/提案のメール通知、不適切掲載の通報・非表示、相手先指定公開、権限の細分化 |
