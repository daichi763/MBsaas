## 応募・認証・個人情報

### D-01 応募のロボット判定ができなかったときは受け付けて「要確認」にする（#501 B）
- **決定**: 公開の募集ページで、Cloudflare Turnstile への問い合わせ（siteverify）が失敗した・タイムアウトした（5秒）ときは、応募を拒否せずに受け付け、`recruit_applications.turnstile_unverified = 1` の印を付ける。管理画面の応募一覧に「要確認」の印を出し、絞り込める。判定に落ちた（`success = false`）応募は今までどおり受け付けない。IP ごと・電話番号ごとの回数の制限は印の有無にかかわらず効かせる。
- **理由**: Cloudflare 側の障害で応募が止まると、募集の機会を失う。いたずらは回数の制限と、管理者の承認（承認しないとシフトにならない）で止められる。
- **根拠のコード**: `src/recruit.ts:295`（判定）、`src/recruit.ts:319`〜`326`、`src/recruit.ts:950`〜`951`（一覧の絞り込み）、`migrations/0087_followups_b.sql:17`

### D-02 パスワード再設定の画面に Turnstile は付けない（#382 A。変更なし）
- **決定**: 再設定のメールを送る画面には、IP ごとの回数の制限（`login_attempts` の `scope = 'reset_ip'`）だけを置き、Turnstile は付けない。応答の文言は、アカウントの有無によらず同じ。
- **理由**: 回数の制限で足りると判断した。さらに本番は今メールを送っていない（D-31）。
- **根拠のコード**: `src/api.ts:579`、`src/api.ts:587`〜`592`

### D-03 他社との共有範囲は A 案（同意の版 v3）（#9001）
- **決定**: 企業間のスタッフ連携で、連携先に見せるのは次の範囲だけにする。
  - 共有する: 氏名・フリガナ・性別・**年代**（生年月日から計算。生年月日そのものは渡さない）・所属会社名と所属先担当者名・最寄駅・通勤可能時間・稼働開始可能日・稼働可能エリア・スキル・経歴・PR ポイント。
  - 共有しない: 従業員管理の情報（雇用形態・給与・手当・口座・住所・社会保険と雇用保険の番号・緊急連絡先など）、連絡先（電話・メール）、生年月日、**備考**（所属元だけの項目）、履歴書などのファイル、所属元の社内メモ・評価・フォロー履歴。
  - 連携先は、所属元の行の基本項目を**その場で読む**（写しを持たない）。連携先は基本項目を編集できない（403）。
  - 同意の文面の版は v3。同意した版と範囲は `roster_consents` に残る。v2 からは共有を減らす変更なので、既存の連携の同意の取り直しはしない。
- **理由**: 他社に渡す個人情報を、仕事の割り当てに要るものだけにするため。
- **根拠のコード**: `src/roster.ts:173`〜`188`（`CONSENT_VERSION`・`SHARED_SCOPE`・`NOT_SHARED_SCOPE`・`ROSTER_OWNER_ONLY_FIELDS`）、`src/lib/tenant.ts:39`〜`46`（他社に返すメールアドレスを伏せる）。詳細は [spec_multi_company_staff.md](spec_multi_company_staff.md) の 6.1。

### D-04 連携先の電話番号は照合にだけ使い、所属元から照合のときに読む（#123 C）
- **決定**: 所属元で電話番号を変えたとき、連携先の行に番号を写さない。連携先で「同じ人か」を電話番号で照らす（応募と既存のスタッフの照合など）ときは、所属元（雇用元）の行の今の番号をその場で読む。照合の結果にも番号は入れない。所属元が連携を終えた行は、所属元の番号を見ない。
- **理由**: 連絡先は共有しない（D-03）。写すと連携先の DB に番号が残る。一方で、古い番号で照合して別の人と取り違えるのも防ぎたい。
- **経緯**: 2026-10-20 の判断では「連携先の行の番号も更新し、照合にだけ使う」としていたが、実装では写さずに照合のときに読む形（C）にした。
- **根拠のコード**: `src/staff-lifecycle.ts:88`〜`94`（`MATCH_PHONE_SQL`・`withSharedPhone`）、`src/staff-lifecycle.ts:70`（`findStaffByPhone`）

### D-07 端末の時刻で記録できるのは12時間前まで・端末の時刻で遅刻を判定する（#427 ①今のまま ②a）
- **決定**: 電波がない場所で押した勤怠の報告は、端末の時刻（押した時刻）で記録する。受け付けるのは、サーバーが受け取った時刻から12時間前まで（2分を超えて先の時刻は受け付けない）。遅刻の判定にもその時刻を使う。
- **理由**: 地下の売り場など、電波がない現場で押した時刻を残すため。本人が時刻を作れる危険はあるが、端末時刻の印（`time_source = 'device'`）・受け取った時刻の記録・ダッシュボードの「端末時刻」の表示で見分けられる。
- **根拠のコード**: `src/report-settings.ts:211`〜`216`

### D-08 報告用URLに本人確認は入れない（#532 A。今のまま）
- **決定**: ログインのないスタッフが使う報告用URL（`/r/:token`）に、電話番号の下4桁などの本人確認は入れない。2台以上の端末から報告されたシフトは、精算の確認事項に出す。同じ会社の管理者がログインしているブラウザからの報告は 403 で止める。
- **理由**: 現場で手間なく報告できることを優先した。なりすましは端末の数の印で気づける。
- **根拠のコード**: `src/settlement.ts:178`、`src/settlement.ts:265`

## 運用・技術

### D-30 Workers の Free プランで動かす・PBKDF2 は 10,000 回
- **決定**: 本番は Cloudflare Workers の Free プラン（CPU 時間は1リクエストあたり 10ms）で動かす。パスワードのハッシュ（PBKDF2）は、作るときは 10,000 回にする。照合は 100,000 回まで受け付ける（Paid プランに移って回数を上げても、古いハッシュで照合でき、ログイン成功時に作り直す）。
- **理由**: 費用を抑えるため。100,000 回では Free プランの CPU 時間に収まらない。
- **影響**: 重い処理は D1 の SQL に寄せる、Web Push は本文を暗号化しない、など（[architecture.md](architecture.md) の 13 章）。
- **根拠のコード**: `src/lib/auth.ts:10`〜`13`

### D-31 メール送信（Resend）は保留・パスワードの再設定は管理者が再発行
- **決定**: 利用者の Resend のアカウントの準備ができるまで、メール送信は保留にする。本番には `RESEND_API_KEY` を登録しないので、本番からメールは送られない（送信の記録には「送信失敗（設定なし）」で残る）。パスワードを忘れた人には、管理者が仮パスワードを再発行する。
- **根拠のコード**: `src/services/email.ts:82`〜`85`（`mailMode`）、`src/accounts.ts:327`（管理者の再発行）、`src/accounts.ts:364`（本部の再発行）
- **再開するとき**: [operations.md](operations.md) の「シークレット」の手順で `RESEND_API_KEY` と `RESEND_WEBHOOK_SECRET` を登録し、`MAIL_FROM` を Resend で認証した独自ドメインの送信元に変える（`wrangler.jsonc:75`）。

### D-33 `test-history` と `test-w4-notifications-mail` は直さない
